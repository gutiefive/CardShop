# Card Shop Empire conventions

Active engine: Godot 4.6.3 standard edition, typed GDScript, Compatibility renderer. Project lives in Game/. Unity was superseded at the user's request; its original scaffold remains in commit 828924b. Do not restore Unity dependencies or introduce C# tooling without a new requirement.

Use the existing checkout. Cloud tasks are isolated; do not create worktrees unless requested. The user reviewed M1–M3 and authorized M4 stocking, customer AI and checkout. Active scope is this session-only retail loop. No reordering, price controls, progression, save system, online services, paid APIs or unrelated systems; M5 requires a further instruction after M4 review.

Use feature folders, explicit exported NodePaths and typed references. Never wire gameplay by searching scene object names. Interactable defines the shared contract; InteractionController owns ray/range/occlusion logic. Authored products, players, sets, rarities and cards are Resources with globally unique stable IDs; prices are integer cents. CardCatalog validates complete set checklists and registered references. Definitions are authored data, never owned card instances. CardCollection owns session copy counts. PackSession coordinates finite starter inventory and atomic collection grants; CardPackDefinition owns validated weighted draws. Do not mutate authored Resources during play. A pack is granted once on opening; skipping reveals keeps those cards. RetailSession owns stock/reservations/revenue; RetailDirector and ShopCustomer own presentation and aisle routing. Only checkout credits a reserved order, once. Never put state-changing initialization inside assert(), which is omitted in release builds. Customer paths are authored for the generated layout; test all routes after moving furniture. Keep data validation independent of presentation. Commit .gd.uid files and .tres/.tscn sources, never .godot or build outputs.

ShopBuilder owns scenes/starter_shop.tscn. Generation replaces that file, not arbitrary user scenes. Preserve custom edits in a separate scene before regeneration. Editor-menu generation requires confirmation. Do not duplicate gameplay logic in generator or interactable subclasses. Use primitive, original placeholder art.

Validation: run Godot editor import, tools/generate_shop.gd when generator changes, tests/run_tests.gd and a main-scene smoke run. Tests must exit nonzero on failure; inspect stderr too, since engine parser/runtime errors can occur with zero exit status. Document exact engine, counts and limits. Headless physics/UI-state tests do not prove desktop rendering, physical mouse capture, real button clicks or Windows exports. The user reported the desktop M1 smoke test passed. Editor-menu regeneration and Windows export remain separately unverified.
